# 决策记录

## 2026-07-17 22:47 — 视觉与实现边界

- **选择**：采用蓝白品牌资产库与深蓝运营驾驶舱方向，集中主题变量并复用既有 Blade 组件。

## 2026-07-17 23:54 — 公开前台主题适配路径

- **否决理由**：仅改 fallback 在默认配置下不可见；强制切换会改变现有站点配置。

## 2026-07-18 09:45 — 后台恢复原版结构后做最小瑞幸换肤

- **选择**：后台运行文件以 `upstream/main@67abfd8` 为结构基线，仅在原页头品牌槽、登录页和公共后台布局接入官网 Logo 与 `#172991` 主题色。
- **备选**：保留侧栏重设计与固定瑞幸演示模块，或继续使用混合前后台的 `luckin-theme.css`。

## 2026-07-18 10:14 — 后台首页使用官网饮品横幅增强首屏

- **选择**：复用官网归档内 1920×300 饮品横幅，只替换 Dashboard 原标题操作区，并用 `.luckin-dashboard` 限定样式。
- **备选**：重新编排 Dashboard 模块，或用 CSS 自绘鹿头、咖啡杯和装饰纹理。
- **否决理由**：用户允许复用真实视觉资产，但仍要求后台原结构；官方横幅能提升品牌识别且不引入自绘 AI 视觉。

## 2026-07-18 10:24 — 后台页脚统一使用官方白色品牌标识

- **选择**：全后台页脚复用官网归档白色鹿头与中英文组合标识，搭配瑞幸深蓝背景，并保留 GEOFlow 原链接、项目介绍入口和运行脚本。
- **备选**：沿用原白底文字页脚，或自绘简化图标与装饰。
- **否决理由**：官方白色标识在深蓝底上识别清晰，也符合用户“真实视觉资产、只做品牌化包装”的要求；自绘资产会产生不一致的 AI 视觉。

## 2026-07-18 11:03 — 瑞幸 MCP 采用异步检测与商品白名单

- **选择**：固定官方 MCP 地址，仅允许门店与商品四项工具；定时命令负责握手检测，Dashboard 只读本地缓存，令牌仅从 `LUCKIN_MCP_TOKEN` 读取。
- **备选**：Dashboard 打开时实时握手，或同时开放预览订单、下单、查单和取消订单工具。
- **否决理由**：同步握手会拖慢后台请求并放大故障面；订单能力超出本次商品知识场景，也需要独立的用户确认、鉴权与审计设计。

## 2026-07-18 11:42 — 瑞幸 MCP 复用 GEOFlow 知识与 RAG 链路

- **选择**：官方结果经字段投影和一次性服务端令牌进入现有知识库，切片成功后两阶段发布为已审核，并沿用任务绑定与 RAG 召回。
- **备选**：只在 Dashboard 展示能力说明，或另建一套 MCP 数据表和独立生成流程。
- **否决理由**：说明卡不构成接入；重复数据系统会绕开 GEOFlow 已有知识治理、切片、任务和证据链。

## 2026-07-18 12:03 — 官方快照保持不可变并迁入自有 fork

- **选择**：瑞幸 MCP 快照发布后禁止人工编辑，详情、重切片和删除采用资源级超管授权，通用素材 API 不允许修改或删除该快照；项目 `origin` 切到 `garetneda-gif/GEOFlow` fork，原 demo 仓库保留为 `demo` 远端。
- **备选**：允许超管直接改写官方快照，或继续把开发分支只推到独立 demo 仓库。
- **否决理由**：直接改写会绕过字段投影并继续携带官方来源标识；自有 fork 能保留与上游的父子关系，同时承载本项目分支和页脚链接。

## 2026-07-18 14:52 — 使用 Vercel PHP 与 Supabase 承载生产演示

- **选择**：Vercel 使用 `vercel-php@0.7.4` 运行 Laravel，Supabase 免费项目提供 PostgreSQL；业务表放入 `luckin_geoflow` schema，Serverless 请求使用 6543 连接池。
- **备选**：改写为 Node 前后端、继续使用 SQLite，或租用常驻 PHP 主机。
- **否决理由**：重写会偏离现有 GEOFlow；SQLite 与 Vercel 只读文件系统不适合生产写入；常驻主机会增加本次演示部署成本。

## 2026-07-18 14:52 — 通过显式代理信任保持生产 HTTPS

- **选择**：仅在设置 `TRUSTED_PROXIES` 时启用 Laravel 代理信任，Vercel 生产环境设为 `*`。
- **备选**：全环境无条件信任所有代理，或强制所有 URL 使用 `APP_URL`。
- **否决理由**：条件启用既能正确处理 Vercel 的转发协议头，也不会扩大本地和其他直连部署的信任边界。
